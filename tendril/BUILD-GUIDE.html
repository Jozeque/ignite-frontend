0Max editor basics read first

If Max is new: a device is a patcher — boxes (objects) connected by cords. Signal generally flows top → bottom. Each object has inlets on top and outlets on the bottom; hover to see what each does.

  • New object: unlock the patch (Cmd/Ctrl‑E), double‑click empty canvas (or press n), type the object name, click away.
  • Connect: drag from an outlet (bottom nub) to an inlet (top nub). An audio connection shows a thick striped (yellow/black) cord; control messages show a thin cord.
  • Edit vs play: Cmd/Ctrl‑E toggles edit/locked. Locked = you can click dials/play.
  • Presentation Mode (the UI Live shows): Cmd/Ctrl‑Opt‑E. Objects must be added to presentation (right‑click → Add to Presentation).
  • Inspector (object settings — crucial for parameters): select an object, open the inspector (the ⓘ in the toolbar or Cmd/Ctrl‑I).
  • Use dark theme (matches these diagrams): Max menu → Options → … theme, pick a dark one.
Workflow that saves the most time
Build §3 (P0) completely and get sound first. Everything after is expansion. Don't wire the whole thing before you've heard one voice.

1Create the device

  1. In Live: drag a Max Instrument onto a MIDI track (Max for Live → Max Instrument → Max Instrument).
  2. Click the edit (pencil) button on the device title bar → Max opens the patcher.
  3. You'll see the instrument template: roughly [midiin]→[midiparse] and an audio output [plugout~]. Keep [plugout~] — that's your audio out. You can delete the demo synth objects between them.
  4. Cmd/Ctrl‑S → save as TENDRIL.amxd (somewhere in your User Library).

2Load the wavetables

First run the generator (one time): cd tendril/data && node gen-wavetables.js → makes tendril_wt_a.wav and tendril_wt_b.wav. Put those next to the device (or use full paths). Then add two buffer~ objects:

3P0 — one voice you can hear ★

This is the whole point of P0: ~7 objects, hear a morphing tone, read the CPU. Build exactly this:

P0 single voice. Yellow = audio cords. notein drives pitch+gate+env; gen~ makes the sound; live.gain~ → plugout~ to Live.
  1. Make [gen~], double‑click it, delete contents, add a [codebox], paste all of gen/tendril_voice.genexpr, connect codebox out1 → the gen~ patcher's [out 1].
  2. Wire [notein] pitch → [sig~] → gen~ inlet 1. (Pitch is fed as a signal; the genexpr does mtof internally.)
  3. [notein] velocity → [> 0] → [sig~] → gen~ inlet 2 (gate).
  4. [notein] velocity → [adsr~ 5 80 0.7 200] → gen~ inlet 3 (the amp envelope; gen~ multiplies by it).
  5. gen~ outlet → [live.gain~] → [plugout~] (both inlets for L/R).
  6. One param to prove the pattern: [live.dial] → [prepend a_tone] → gen~ leftmost inlet. Sending a_tone 0.5 sets that Param.
If it's silent
Check: buffers loaded (click them — waveforms visible)? Audio on in Live? A note held so adsr~ output (inlet 3) is > 0? Pitch reaching inlet 1 (~60)? Codebox compiled with no red errors (look at the Max Console, Cmd/Ctrl‑M)?

4Parameters & the inspector

Every live.dial that should be automatable (and visible to Stride) needs inspector settings. Select the dial → open inspector → set it like this (values come from tendril-params.js):

Why Float + 0–127 (the on/off trap)
Stride writes a BoolEvent (true/false) or IntEvent (rounded) when a parameter's Type is Bool/Int — that's what makes it inject as ON/OFF. A Float param injects smooth values. Use Type = Float and range 0.–127. to match Ableton's macro convention Stride is tuned for. Then scale into gen~: [live.dial 0.–127. Float] → [/ 127.] → [prepend a_tone] → gen~ (gen~ wants 0–1). Real-ranged params (Pitch ±24, Octave ±2, Fine ±50) stay Float at those ranges, no /127.
  • Long Name = what Live automation & Stride show. Scripting Name = unique id, must match the Param in the genexpr. Turn on Link to Scripting Name to keep them unified.
  • Exponent ~3 for the log:true rows (cutoff, glide, times) so motion feels perceptual.
  • Selectors (ftype, dtype): use [live.menu], set Visibility = Stored Only (hidden from automation — they're hand‑set, not Stride lanes).

5Hear it + read CPU the gate

  1. Lock the patch (Cmd/Ctrl‑E), play a note on the track. You should hear a morphing wavetable tone.
  2. Turn Tone / (add Body, Air, Cutoff) — confirm it's musical across the whole range of each (that's the modulation‑safe promise).
  3. Turn on Live's CPU meter. Note the cost of one voice. Then go to §7, wrap in [poly~] at 8 voices, and re‑check.
The decision
If 8 voices of this dual‑osc engine is affordable on a mid machine → green light to build the rest. If it's heavy → we switch poly~→MC, trim wavetable partials, or drop voice count. Report the number back to me.

6The voice patcher

To go polyphonic, the voice must be its own patcher that poly~ clones. Save this as tendril_voice.maxpat (next to the device). One clean trick keeps it tiny: one [route midinote] splits note messages from parameter messages — and parameter messages pass straight into gen~ (gen~ accepts "name value" Param messages on its left inlet).

tendril_voice.maxpat · [route midinote] splits notes from param messages; params flow straight to gen~.
Why this is clean
Because gen~ accepts "paramname value" messages directly, you don't need a prepend per parameter inside the voice — every param message just falls through route's right outlet into gen~.

7poly~ (8 voices)

At the top level, host the voice with poly~. Notes are auto‑allocated with the midinote message (allocation ignores target, so global params can use target 0 safely).

Top level. Notes → "midinote p v" (auto‑allocated). Params → "target 0, name value" (all voices). Both enter poly~ inlet 1.
The one gotcha
Send notes as midinote (auto voice‑allocation, unaffected by target). Send params with a leading target 0, so every voice updates. If params don't reach voices in your Max version, that's the spot to check.

8Full param surface + ORDER critical

Create one control per stride:true row in tendril-params.js (49 of them), each with inspector settings from §4. They can sit in a tidy grid off to the side — only the inspector matters functionally; the pretty layout is the jweb UI (§10).

Order = the Stride API
Stride injects automation by parameter position (envelope_index). Create the dials in the exact index order 0,1,2,… of tendril-params.js. Verify in Max's Parameters sidebar (the list view) and drag to fix order if needed. Never insert in the middle later — append only (the reserved slots are there for this).

This is exactly what burned v1.2.0 of Stride (positional misroute). Get the order right once.

Verify with Stride
Launch Stride → Scan Mapped. You should get exactly the ~49 named lanes, in order, no junk. That's your contract confirmed.

9FX builder — matrix~ + ABL + feedback

Engines: ABL objects (Ableton's real devices, Max 9) for the modules they nail; gen~ for the safety‑critical feedback limiter. Each module is wrapped behind ONE macro dial.

Schematic. Blue = ABL (Ableton engines). Tan = gen~. matrix~ sets order/parallel; dashed = the self‑limited feedback loop (feedback→distortion stays musical).
  • Use the exact ABL object names your Max exposes (check the abl.device.* list). Standard, not mc. variants (those aren't licensed for M4L distribution).
  • Each macro dial (e.g. fx_drive) drives a curated path into the ABL device's params + auto makeup. Never expose raw ABL params to Live/Stride.
  • Feedback gen~ = gen/tendril_fx_feedback.genexpr. Tap post‑chain → its in1; its out1 sums back pre‑slot. fx_fbamt/fx_motiontime control it.

10The jweb UI

Add [jweb @file ui/tendril-ui.html]. The UI auto‑builds all knobs from the contract and talks to Max via window.max. Wire both directions:

jweb bridge. Left outlet → params (page→Max). Right: send "set name value" into jweb to echo values / glow (Max→page).
  • Presentation: put [jweb] in Presentation Mode, sized to the device strip. Add an "Open" button ([live.text]) → [thispatcher] to pop a floating resizable window for the full UI.
  • Freeze caveat: a frozen device can't load the HTML into jweb directly — use the executejavascript‑after‑onloadend injection (h1data/M4L‑jweb‑injection). Build unfrozen first.

11Stride glow bridge optional

Add [node.script tendril-bridge.js]. It connects to Stride on localhost:9100 and emits glow/glowoff messages. Route those into [jweb] so knobs pulse in their lane color while Stride injects. Pure cosmetics — skip for P0. Needs the ws module available to node.script.

12Freeze & ship

  • Confirm param order via Stride Scan Mapped; confirm CPU at target voices; confirm a feedback→distortion patch at max stays musical.
