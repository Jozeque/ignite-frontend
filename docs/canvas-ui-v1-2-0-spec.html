What changed

Each numbered orange dot maps to one fix below.

1
Apply to Clip — promoted in TOP action zone (not moved)
Stays in its current location (above Save/Load) but uses orange→red brand gradient, ~50% taller, with an inline "Drag the .alc into Ableton" hint. Was a thin emerald bar at the same weight as Save/Load. P2 · 2hrs
2
Template status pill — already exists, retained
"Template Ready" (green) / "No Template" (red) below the rack name. Audit called this out as something that's already great — visualized here so it doesn't get redesigned away. P0 · 0hrs (no change needed)
3
Generate (cloud) — kept in toolbar, label clarified
Currently visible only in online mode (license signed in). Added a tiny "cloud" sub-label so it's clearer this is the cloud-generated curves+MIDI panel, not the local Generative section in the sidebar. P1 · 15min
4
Loop pill — consistent padding (no rebuild jump)
Static HTML used px-2 py-0.5; JS rebuild after first click switched to px-3 py-1. Buttons grew on first interaction. Both sides now px-2 py-0.5. Same fix on Tool buttons. P0 · 45min
5
Toolbar Row 2 — category labels (Edit / Generate / Time / Select)
Same pattern Row 1 already uses for "Shapes:" / "Saved:". Producers no longer need to read every button label to figure out grouping. Includes Swing (was missing in rev 1). P2 · 1.5hrs
6
Multi-view scrolls vertically when params > visible area
"8 / 30" indicator + violet scrollbar thumb on the right. NEW: wheel-scroll handler (was missing — audit flagged as #1 producer expectation). Each lane stays ~50px when sidebar is open; if rack is huge, user scrolls the canvas. P2 · 1.5hrs
7
Keyboard shortcuts — always visible as <kbd> chips
Was hidden behind xl: breakpoint. Now persistent in dock. New: Ctrl+Z undo, Ctrl+S apply (wired to existing sdUndo / sdRedo). P2 · 2hrs
8
Titlebar buttons → icon-only with tooltips
Reclaims ~140px on the right side of the titlebar. Account icon also pinned here (currently buried in Generate panel flow). Matches DAW conventions. P3 · 3hrs
9
⚠ NAMING CONFLICT — "Generate" (toolbar) vs "Generative" (sidebar)
These are two completely different features sharing the same root word:
  • Generate (toolbar, orange) → cloud panel: pick style / BPM / key → curves + MIDI come back from server. Online-only, gated by sign-in + credits.
  • Generative (sidebar) → local tools: Chaos / Bloom / Prism. Manipulate existing curves on the canvas. Always available, no network.

Recommendation for v1.1: rename one of them. Options:

  • Toolbar "Generate" → "Cloud" or "Compose" (matches it being a network-y thing)
  • Sidebar "Generative" → "Tools" or "Variants" or "Spread" (matches it being a local manipulation row)

I'd lean: keep "Generate" for the toolbar (cloud is the headline V2 feature) and rename sidebar to "Variants" or "Spread". Your call though. P1 · 30min once decided

  • · Toolbar buttons standardized (24px touch targets where possible)
  • · Modal close-buttons unified (SVG X in 24px square button)
  • · Modal headers unified (gradient for "feature" modals, plain caps for "task" modals)

  • · Drop unused Outfit font-weight 300 (~20kb saved per cold start)

Open questions for you before build

  1. 1. Generate vs Generative naming. Pick a side (see annotation #9). My lean: rename sidebar "Generative" → "Variants" or "Spread."
  2. 2. Sidebar width. Keep at 224px or bump to 256px? Wider sidebar = roomier sliders, but eats canvas width. Test against your typical rack size.
  3. 3. Toolbar Row 0 layout. Currently centers Presets with empty right column for grid-balance. With Generate added, it gets crowded. OK to drop the centering and just left-align everything?
  4. 4. Account icon in titlebar. Currently the Account panel only opens via Generate (signed-out flow). Adding it to titlebar means it's always one click away — but adds another titlebar button. Worth it?
  5. 5. "Clear Lane" tooltip wording. "Clear curves on the active lane (locked lanes are skipped)" — is "skipped" clear enough or does it need "ignored / not affected"?
