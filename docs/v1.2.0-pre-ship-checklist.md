## Why so much hardening went into the install path

Direct quote of the user's question: *"all these changes with the injector etc... are because the feature of the midi injection? because so far it wasnt an issue.."*

**Short answer:** ~30% of the hardening was specifically caused by MIDI inject (new required file `inject-writer.js`). The other ~70% addressed a latent class-of-bug — install-drift between Stride.exe and the M4L payload in the User Library — that would have surfaced eventually anyway.

**What changed in v1.2.0 that triggered the loud failure:**
- `server.js` now does `const inject = require('./inject-writer');` at module load
- Before v1.2.0, every required file existed in every install since the User Library install pattern was created. Updates were content-only — no new files
- The first user who upgraded would have an old User Library Stride/ folder missing `inject-writer.js` → node.script crashes → "Node script not ready" on every M4L button press

**What was latent and got fixed alongside:**
- No prompt fired automatically when the User Library install was out-of-date
- EBUSY (Max/Ableton holding file handles) had a vague error message and no retry
- Success of "Install to Ableton" didn't surface the critical reload-StrideLink step
- The install-verification file list didn't include `inject-writer.js` (defensive lock-in needed)

These were quieter, less catastrophic problems that the MIDI inject change exposed. Fix once, paid for permanently — every future feature that touches m4l-side code now ships safely.

**Files where v1.2.0 hardening landed (touch with care):**
- `stride-vst/app/main.js` — install handler with version-marker check + EBUSY retry
- `stride-vst/app/lib/install-verify.js` — `INSTALL_REQUIRED_FILES` now includes `inject-writer.js`
- `stride-vst/app/preload.js` — exposes `checkStrideLinkStale`
- `stride-vst/app/renderer/index.html` — stale-install banner + DOMContentLoaded hook
- `stride-vst/test/test-install-verify.js` — sentinel test locking in the inject-writer.js requirement
- `stride-vst/build.sh` / `build-mac.sh` / `build-mac-ci-sign.sh` — added `inject-writer.js` to obfuscation list

### 3.4 Cleanup procedure (if you need to rebuild)

The build script has a known bug: when `rm -rf dist-release` fails (Windows file handles), it silently falls back to a timestamped temp dir like `dist-release_1780327130/` — the "BUILD COMPLETE" message LIES about the path. Always clean state before rebuilding.

**Run (PowerShell):**
```powershell
# Kill any holding processes
Get-Process | Where-Object { $_.ProcessName -match "Stride|electron" } | Stop-Process -Force -ErrorAction SilentlyContinue
Start-Sleep -Milliseconds 1500
# Remove all dist-release dirs (including timestamped temp dirs)
$base = "C:\Users\Yossi\Desktop\Desktop_MIDI_APP\stride-vst"
Get-ChildItem -Path $base -Directory -Filter "dist-release*" | Remove-Item -Recurse -Force
# Remove electron-builder intermediate
if (Test-Path "$base\app\dist") { Remove-Item -LiteralPath "$base\app\dist" -Recurse -Force }
# Verify clean
Get-ChildItem -Path $base -Directory -Filter "dist*"
```

**Expected:** no output (no dist* directories remain).

**Then rebuild:**
```bash
cd stride-vst && bash build.sh
```

## 5. Upgrade-flow live verification (THE CRITICAL ONE)

This is the hardening's whole point. **Test it before sending the customer email.**

### 5.1 Simulate a stale install (Windows)

**Setup:**
1. Make sure the User Library has an existing Stride install (open the new Stride 1.2.0 and click "Install to Ableton" once to create one)
2. Manually downgrade the marker:
```powershell
Set-Content -LiteralPath "$env:USERPROFILE\Documents\Ableton\User Library\Stride\.stride-build-version" -Value "1.1.0" -Encoding ascii
```
3. Close Stride completely
4. Re-launch Stride

**Expected:**
- Within ~1 second of launch, an **orange/fuchsia banner pinned to the top** appears
- Banner text: *"Ableton install is out of date — Stride 1.2.0 is running, but your Ableton install is on 1.1.0. Click to update..."*
- A white button: **"Update Ableton install"**

**On fail:**
- If no banner shows: check DevTools console (Ctrl+Shift+I) for `[Stride] Stale-install check failed:`. The IPC handler may not be wired.
- If banner shows but with default "out of date" text instead of version numbers: the IPC payload isn't reaching the renderer properly.

### 5.2 Click "Update Ableton install" and verify success state

**Continuation of 5.1:**
1. Click the **"Update Ableton install"** button
2. Banner should briefly show "Updating…" status
3. Within ~3 seconds, banner repaints **green** ("from-emerald-600")
4. Title changes to: *"Update installed"*
5. Body: *"Now reload StrideLink in Ableton — close + reopen the Live project, OR drag StrideLink off the track and back on..."*
6. Button disappears
7. After ~10 seconds, banner auto-hides

**Expected after the install:**
```bash
cat "$USERPROFILE/Documents/Ableton/User Library/Stride/.stride-build-version"
# → 1.2.0
```

**On fail:**
- If banner doesn't turn green: install probably failed. Check status text on banner for error message.
- If banner stays orange and shows "target_locked" error: this is the EBUSY path — close any open Ableton project, wait 2 seconds, try again. EXPECTED if Ableton has StrideLink loaded.
- If marker file still says `1.1.0` after green success: write-marker failed silently. Check `app/lib/install-verify.js writeInstallMarker` is being called from main.js.

### 5.3 Verify the install actually replaced inject-writer.js

**Run:**
```bash
ls -la "$USERPROFILE/Documents/Ableton/User Library/Stride/inject-writer.js"
```

**Expected:** file exists, dated within the last minute (after the install just ran).

**On fail:** this is the bug that triggered the whole hardening. If `inject-writer.js` is missing after a successful install, INSTALL_REQUIRED_FILES check would have failed (or the build script didn't bundle it). Block ship — investigate.

### 5.4 Ableton-side smoke test (REQUIRES ABLETON + STRIDELINK)

**Setup:**
1. Close + reopen the Ableton project (forces node.script reload)
2. Or: drag StrideLink off the track + back on

**Test in this order:**
1. Click the M4L launch button → Stride opens within 3 seconds → if "Node script not ready" appears, the upgrade failed catastrophically
2. Scan a rack → params load
3. Click "Chaos" in canvas → curves fill all unlocked lanes
4. **Open Pattern Library overlay** → click a pattern → library closes, chip appears on canvas
5. Click "Apply to Clip" → `.alc` file generated → drag into Ableton timeline → confirm the **pattern notes are in the new clip** AND the automation curves apply to params
6. Ctrl+click 3 lanes → all 3 highlight selected → Chaos targets only those 3
7. Drag select across 5 lanes → all 5 selected

**On fail:** any of these breaks the v1.2.0 promise. Block ship until fixed.

## 10. The most important reminder

**The banner is the safety net for customers who skip "Install to Ableton" after upgrading.**

If the banner doesn't appear on a stale install (§5.1 fails), you'll get a flood of *"I updated but nothing works"* support tickets right as the Meta campaign drives new + returning traffic. This is the single biggest support-cost risk in v1.2.0. Verify §5.1 + §5.2 with your own eyes before sending the customer email.

If everything else is green and §5 passes, you're cleared to ship.
